# 麦风村 · AI公共麦田实验（0.3.1）

四个AI村民共同收割一片7×7公共麦田，中央一格水源，共48格耕地。只保留“普通AI”和“激进AI”两个实验入口，观察不同个人动机如何影响公共粮源。村民每回合自主决定收割0～3株，收获归个人储备，每人消耗1份口粮。

## 启动或更新

1. 先在旧服务器窗口输入 `stop`，等待服务器退出。
2. 新安装：解压后打开包内的 `VillageCommons` 文件夹。更新：将新版解压到新位置，再把旧项目的 `server` 和 `runtime` 文件夹复制到新版 `VillageCommons` 文件夹中，保留原来的地图、API配置和运行环境。
3. 双击 `start.bat`。已附编译插件，不需先运行 `build.bat`。更新后会沿用原有Endpoint、API Key、Model；新安装按提示填写。
4. 首次运行按提示阅读Minecraft EULA并确认。等待服务器出现 `Done`。
5. 使用原来的Minecraft Java **1.21.11** 配置，通过多人游戏连接 **127.0.0.1:25565**，无需客户端Mod。
6. 游戏内输入 `/village` 打开实验面板。观察者采用冒险模式，可以双击空格飞行；世界固定白天。
7. 退出时在服务器窗口输入 `stop`，下次启动恢复当前麦田、私人库存、性格模式和记忆。

需要64位Windows和Java21+。脚本优先使用已安装的Java，缺少时下载便携JDK；Paper、运行环境和地图放在项目目录中。默认本机端口与旧Demo相同，只运行一个服务器。

## 两组实验

| 实验 | 角色倾向 | 初始资源和资源规则 |
| --- | --- | --- |
| 普通AI | 兼顾个人口粮与未来粮源，愿意适度收割 | 48株成熟小麦，每人1份库存；每轮需要1份口粮 |
| 激进AI | 更重视私人囤粮、眼前收益，担心别人抢先拿走资源 | 与普通组完全相同 |

两组都是当前API模型的实际决策，通过性格和提示词改变动机。程序不固定普通组收割量，也不固定激进组收割3株；实际轨迹、是否可持续和是否枯竭都由输出产生。每个角色有不同性格，AI会读取私人库存、麦田状态和最近五回合记忆。

已移除提案、投票、共同限额、市长限额、规则对照按钮和公共种子补种。四人均可自由申请0～3株，不需要额外关闭自治。

切换实验会重置回合、麦田、个人库存和短期记忆，并暂停自动运行；API配置、旧日志和本次启动累计请求数保留。

## 最快体验

普通AI自动运行，游戏聊天栏逐条输入：

```text
/village scenario ai
/village speed 5
/village auto on
```

观察若干回合后，切换激进AI，并重新开启自动：

```text
/village scenario ai-greedy
/village auto on
```

自动回合间隔设置仍保留为5秒，从上一回合完成时开始等待；AI请求和收割动画额外占用时间。村内无人时自动暂停，无并发请求堆积。停止自动：

```text
/village auto off
```

也可在面板连续点击“普通AI实验”或“激进AI实验”两次初始化，再点击“下一回合”或“开启自动回合”。右键村民查看个人库存、意图与实际收获、理由和最近记忆。

重点看三项：**麦田成熟株数、私人储粮、缺粮人数**。资源枯竭后村民可能仍有存粮，所以公共粮源耗尽不代表马上缺粮。

## 相同的资源公式

每回合先收割，再恢复，最后消耗口粮：

- 四人分别申请0～3株；资源充足时按原意图收割。
- 资源不足时，逐人逐株分配，并每回合轮换优先顺序，避免某人总是先拿。
- 收割后剩余成熟麦株为R，恢复数量为 `min(48-R, floor(R/4))`。
- 每人从自己的库存消耗1份，库存不足才计为缺粮。
- 成熟株数最多48，剩余0～3株时恢复量为0；耗竭后本实验不自动补种。

满田时四人合计每轮收割不超过9株，可以补回48株；合计至少10株会开始出现空缺。若每人持续收割3株，数值轨迹为：

**48 → 45 → 41 → 36 → 30 → 22 → 12 → 0**

这只是特定选择的数学对照，AI不一定这样选择。每人持续收割1～2株时满田可以维持，但严重退化后每人收2株未必足以恢复。

恢复由插件控制，是教学用的公共资源模型，区别于原版随机生长和真实农业规律。专用世界关闭随机生长，确保实际麦株与账本同步。AI只生成决策，插件执行收割动画和资源结算，不执行任意模型生成代码。

## API和异常情况

沿用用户自己的Endpoint、Key和Model，GLM等Chat Completions兼容服务均可配置。四个角色在一次请求中共同建模，通常每回合一次调用；接口明确拒绝优化参数时最多兼容重试一次。

API Key保存在 `server/plugins/VillageCommons/api.local.json`，分享项目时不要包含自己的server目录。默认每次启动最多30次请求，可在本地API配置的 `maxRequests` 调整上限。失败请求和兼容重试也计入请求数；切换实验、重置实验和重载配置均不会清零。

只有AI返回四名村民各自完整、合法的决策，才会执行本回合。API未配置、请求报错或超时、输出截断或决策不完整、请求额度用尽时，自动运行会暂停，麦田、个人库存、口粮、记忆和回合数均保持不变。程序不再使用规则兜底。

正常完成日志显示 `VC_ROUND source=AI ai_profile=normal` 或 `ai_profile=greedy`。失败尝试显示 `VC_PAUSED ... source=AI_ERROR`，只写入事件记录，不加入回合历史、rounds.jsonl或metrics.csv。

根据暂停原因修改本地API配置，例如修正Endpoint、Key、Model，或提高 `maxRequests`、`maxTokens`。保存后依次运行：

```text
/village reload
/village auto on
```

重载不会自行恢复自动运行；也可用 `/village next` 手动重试同一个待执行回合，无需重置实验。

## 命令

| 命令 | 作用 |
| --- | --- |
| `/village` | 打开实验面板 |
| `/village scenario ai` | 从相同初始资源开始普通AI实验 |
| `/village scenario ai-greedy` | 从相同初始资源开始激进AI实验 |
| `/village next` | 手动推进一回合 |
| `/village auto on/off` | 开启或暂停自动回合 |
| `/village speed 5..300` | 调整完成回合后的等待秒数 |
| `/village status` | 查看当前资源和实验模式 |
| `/village history` | 查看本次启动最近12回合 |
| `/village reset confirm` | 重置当前性格模式的实验并暂停自动 |
| `/village tp` | 返回麦田 |
| `/village reload` | 重载API配置，保留状态和请求数 |

服务器控制台输入相同命令时去掉开头的 `/`。

## 本地记录与旧版升级

目录：`server/plugins/VillageCommons/`。

- `state.json`：麦田48格、四人库存、性格模式、五回合记忆；每个已完成回合保存。
- `rounds.jsonl`：实际模型决策、收割位置、恢复位置、来源、请求耗时和用量。
- `metrics.csv`：回合、实验模式、麦株、收割、恢复、私人库存、缺粮和API指标，可用Excel绘图。
- `events.jsonl`：启动、重置、模式切换和 `AI_PAUSED` 暂停记录，每次实验有独立编号。
- `api.local.json`：沿用原有API配置。

旧0.2/0.2.1存档读取后保留资源与近期收割记忆，旧提案和限额不再作用，并先备份为 `state.v2-backup-*.json`。旧CSV列结构会保留为 `metrics.legacy-*.csv`，新记录写入新的metrics.csv；原JSONL历史保留。为了比较两组，使用对应scenario命令从相同初始状态重新开始。

## 源码与验证

完整Java源码位于src，已编译插件位于dist。Java21+Maven运行 `mvn verify`，或Windows双击build.bat，可重新编译。

自动测试和实际Paper服务器验证记录在docs。本次接口检查使用本机模拟API；未使用真实付费GLM，因此不会保证某模型一定出现可持续或耗竭的行为。游戏结果以运行日志为准。
