# 验证记录

版本0.3.1使用Microsoft OpenJDK21.0.12.1+1编译，交付包包含dist/VillageCommons.jar。本次33项单元测试通过JUnit Platform Console执行，17项集成检查全部通过。

自动测试覆盖：
- 同一套收割、恢复和口粮公式用于两种性格；给定相同意图时结算相同。
- 四人每轮各收3株的七轮耗竭轨迹，每人收1或2株的持续供给，满田总收割10株的衰退边界。
- 私人存粮延后缺粮、资源不足时轮换分配、资源守恒和记忆长度。
- 无投票字段的新JSON协议，旧协议多余提案不影响收割。
- 两种性格进入真实HTTP请求，兼容重试保持性格，模型返回2株时不会被强制改为3株。
- 四人决策缺失、重复、未知ID、非法收割量或非法理由时整体拒绝，结算前也验证决策完整性。
- 未配置API、HTTP错误、截断响应和请求上限不会返回规则决策；失败响应的已报告用量仍计入统计。
- 重载配置保留请求数，提高上限后可以重试；兼容参数重试也受同一请求预算限制。
- 存档恢复与损坏备份，旧版共同规则失效、升级备份、CSV结构升级归档。

集成验证使用Minecraft Java1.21.11 / Paper build132真实启动专用服务器，以及本机模拟API：
- 四个村民、48株实际麦田、中央水源、固定白天和关闭随机生长。
- 真实收割恢复动画与资源账本同步。
- 普通模拟AI持续2株与激进模拟AI持续3株产生对应轨迹。
- 切换实验同初始资源，旧限额或治理命令不能改变状态。
- API未配置、非法JSON、不完整四人决策、HTTP错误和请求额度用尽均暂停自动；成熟麦株、个人库存、记忆和回合数保持不变。
- 请求额度用尽时不再发送HTTP请求；提高上限并重载后，由实际AI决策继续同一个待执行回合。
- 重置忽略迟到响应，重启恢复性格与资源。
- JSONL与CSV只记录已完成的AI回合，暂停尝试只写入事件日志；5秒自动开关生效。

数量、结果和插件哈希以validation-result.json和smoke-result.json为准。未调用真实付费GLM模型，未在Windows桌面Minecraft客户端进行自动试玩。GitHub整理版只修正Windows启动脚本的两处旧“规则基线”提示文字，启动逻辑未变；本环境没有PowerShell，未重新进行解析检查。原脚本已在0.3.0做过解析检查。

## 重现

运行mvn verify。实际服务器验证需已阅读并同意Minecraft EULA：

```text
python tools/smoke_test.py --java JAVA路径 --paper 匹配版本paper.jar路径 --accept-eula --output docs/smoke-result.json
```

可用--cache-dir复用之前的Paper运行依赖。测试使用隔离临时服务器和本地模拟API，不读取用户Key。交付server.properties仍采用在线验证。
