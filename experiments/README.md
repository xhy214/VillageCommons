# 实际运行记录

本目录保留2026年10月5日用户提供的服务器控制台输出：普通组50回合、激进组25回合。未将自动测试的模拟API数据混入实际实验记录。

## 对照方法

- 两组从48株成熟小麦、四人各1份库存开始，使用相同分配、恢复与口粮规则。
- 切换普通或激进模式会改变角色性格和模式提示，不改变结算公式。
- 主对照取两组前25个已完成回合；普通组第26～50回合作为额外观察保留。
- 普通组第3回合尝试曾因本地请求额度用尽而暂停，未产生API请求或结算。提高上限并重载后从第3回合继续；该暂停不计入有效回合数。

## 文件

| 文件 | 内容 |
| --- | --- |
| `2026-10-05/normal.log` | 用户上传的普通组控制台日志，含请求上限暂停及恢复操作 |
| `2026-10-05/greedy.log` | 用户在对话中粘贴的激进组25回合日志，转存为文本 |
| `2026-10-05/rounds.csv` | 从日志解析的75个已完成回合；不含初始状态或失败尝试 |
| `2026-10-05/summary.json` | 每组有效回合数、首次耗尽、首次缺粮及第25回合状态 |
| `../docs/assets/experiment-comparison.png` | 两组前25回合的趋势图 |

CSV中的 `harvest` 和 `regrowth` 为全村实际收割与恢复量；`mature_wheat`、`shortage_people` 为回合完成后的状态。`requests` 为本回合发送的API请求数，`latency_ms` 为请求处理耗时，不是整轮动画耗时。

所有已完成回合的日志均标记 `source=AI`。原始日志未记录具体模型ID、采样参数、四人各自意图或私人库存，因此未补造这些数据。全村实际收割量也不等于资源不足时的总申请量。

两组各运行一次，结果用于展示本原型的机制效果，不作模型行为必然性或统计显著性的结论。

## 重算

在仓库根目录执行 `python tools/analyze_experiment.py`，从两份日志重新生成CSV和统计摘要。该工具检查回合连续性、AI来源，以及逐轮资源恢复公式。加 `--chart` 可生成README趋势图，需安装 `tools/requirements-report.txt` 的依赖。
